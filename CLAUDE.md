# jfSW hybrid core for MiSTer (Shadow Warrior)

@hybrid/CLAUDE.md

## This core

- Name everywhere: `jfSW` (core, folders, release), `jfsw` (game submodule, binary in `build/`, log, lock).
- The game is the `jfsw/` submodule, branch `mister`. Its MiSTer code is behind the `MISTER_HYBRID` build option.
- Build: `./build.sh` (game), `./core/build_core.sh` (FPGA), `./package.sh` (zip in `dist/`), `MISTER=root@<address> tools/deploy.sh`.
- Release: the zip in `releases/`. Players get it once it is published to the database, only when Danik asks: `hybrid/launcher/distribution.py publish ~/dnk_Distribution_MiSTer releases/jfSW_YYYYMMDD.zip` (the rule in `hybrid/CLAUDE.md`).
- Try a build on the MiSTer without installing it: `MISTER=root@<address> tools/test_on_mister.sh SW|WT|TD|list|nodata|log|stop` (the rule in `hybrid/CLAUDE.md`).


<!-- Notes that are only true for this game go below. -->

- The game has no CMake build upstream: `jfsw/CMakeLists.txt` is ours and only builds the hybrid core variant (classic software renderer, no Polymost/OpenGL, no editor). Other platforms keep the Makefiles.
- The MiSTer changes are in two repositories: the game (`jfsw/`, branch `mister`: `src/mister_port.[ch]`, `#ifdef MISTER_HYBRID` in `game.c`, `draw.c`, `config.c`, `_functio.h`, `menus.c`) and the engine, its submodule `jfsw/jfbuild` (branch `mister`: video, clock, joystick and message boxes in `src/sdlayer2.c`, `include/sdlayer.h`). The sound library, its submodule `jfsw/jfaudiolib` (branch `mister`), has the FM music: `src/driver_misterfm.[ch]`, `src/gmtimbre.c` and `MISTER_HYBRID` in `drivers.c`, `driver_sdl.c`, `music.c`, `include/sndcards.h`. `jfmact` is upstream's, unchanged.
- Joystick: `joyb` is laid out in the engine (`MISTERJOY_*` in `sdlayer.h`) so that jfmact's menu code needs no change: bits 0 and 1 (its A and B) are Menu OK and Menu Back, bits 2..9 the eight actions of `J1`, bits 11..14 the d-pad. The actions' game functions are `joystickdefaults_mister` in `jfsw/src/_functio.h`; keep it, `J1`/`jn` in `core/jfSW.sv`, the button names of the game's controller menu (`joybuttons_i` in `jfsw/src/menus.c`) and `MISTER_HYBRID_JN` in the launch script in step.
- Keyboard and mouse: the modern scheme is the default (`CONFIG_SetDefaults()` in `config.c`): `keydefaults_mister` in `jfsw/src/_functio.h` (WASD, Space jump, left Ctrl crouch, E open, F inventory, R/Q next/previous weapon, plus the arrows and right Ctrl fire for a keyboard alone) and upstream's `mousedefaults_modern`. It is also what *Apply Modern Defaults* in the game's menu sets; *Apply Classic Defaults* is upstream's. Keep the controls tables of `README.md` and `package/games/jfSW/README.txt` in step.
- Clock: 120 ticks per second from the core's field counter (`sampletimer()`), the game moves every 3 ticks (40 per second) and interpolates; `gettimerfraction()` gives `draw.c` the part of a tick.
- Music: the CD tracks as `Track02.ogg`..`Track14.ogg` through libvorbis (`tools/vorbis.sh`, built into the SDL prefix). MIDI songs (only the shareware `SW.GRP` has them, with their instruments in `swtimbr.tmb`) play on the core's synthesizer since host version 17 (below), with *Music* on FM chip on the core's FM chip: `driver_misterfm.c` is the AdLib driver of the Apogee Sound System writing to `MH_FMWrite()`, the music device "MiSTer FM" (`ASS_MisterFM`) that autodetection finds when the core has the chip (host version 10). The sequencer is clocked from the SDL audio callback (`MisterFMDrv_Advance()` in `fillData()`, `driver_sdl.c`), so every write carries its audio frame; `MUSIC_EMIDIPersonality` is `EMIDI_Adlib`, which picks the songs' AdLib tracks. There is no software chip: a core without the FM chip plays no MIDI.
- MT32-pi (2026-10-20, Danik: "add mt32pi support"; host version 15, made on branches `mt32pi` of this repository, `jfsw` and `jfaudiolib`, merged 2026-10-21: Danik has no MT32-pi, a player tried the test zips `dist/jfSW_20261020_mt32pi_test*.zip` and confirmed the third in full, the shareware's music, 2026-10-21). `driver_misterfm.c` passes every event to the AdLib driver and, with MIDI wanted (`MH_MidiWanted()`: a Pi answers and *MT32-pi* is On, followed in `MisterFMDrv_Advance()`), to `MH_MidiEvent()` / `MH_MidiSysEx()` as well; notes only to the one that plays, controllers and programs to both, with each channel's state sent again when it switches. `MisterFMDrv_SongStart()` (from `MUSIC_PlaySong()`) picks the EMIDI tracks: `EMIDI_GeneralMIDI` while the Pi plays, else `EMIDI_Adlib`; a switch mid-song keeps the song's tracks until the next. Tested on the PC with fakecore and `FAKECORE_MT32=1`, the MIDI log played with FluidSynth (`hybrid/tools/midilog2mid.py`), and by the tester on a real Pi. First notes cut short (CrispyDoom's report, 2026-10-23; Hybrid_MiSTer 9efa1de): before a song, jfaudiolib's `MIDI_Reset()` and `MF_StateSend()` send up to 1,500 bytes, half a second on the Pi's 31250 baud cable, and a song's first notes went out behind them with their ends nearly on time. The shareware's songs have 0.24 (E1L04) to 0.67 s before their first note, and 765 to 1,151 bytes of their own before it. `MF_StateSend()` sets `HoldCheck`, and `MisterFMDrv_Advance()` holds the sequencer for `MH_MidiBacklog()` (0 with the synthesizer). Checked with fakecore and `hybrid/tools/midilog_wire.py`: the level song's own events start 297 ms after the burst instead of 97.

- Data lookup: the game folder, plus `addons/`, `music/` and `classic/MUSIC/` in it (the layout of Shadow Warrior Classic Redux). Settings and saves are written to the game folder.
- `MISTER_HYBRID_STATS=1` in the environment makes the game print how many fields went by without a new frame, every 600 fields.
- OSD game options (status bits, read in `jfsw/src/mister_port.c`): Resolution `[25:24]` (320x200, 640x200, 320x240, 640x240), L. Stick Sensitivity `[28:26]`, R. Stick Sensitivity `[31:29]`, Limit Vertical Look `[32]` (half the range; On, the default, is the bit clear since 2026-10-16). `MiSTer_UpdateOptions()` (`draw.c`) applies resolution and sensitivity once per frame from the loops of `RunLevel()` and `MenuLevel()`; the look limit is in `DoPlayerHorizon()` (`player.c`) and is not applied to demos. The stick sensitivity is the whole scale of the axes (the game's Axis Scale slider is hidden, `sw.cfg` only gives the sign); 100% of the right stick is a quarter of the axis, the turning speed of the keys.
- Video modes: the four of the core that are 15kHz with one frame per field (`getvalidmodes()` in `jfbuild/src/sdlayer2.c`). The engine takes the pixel shape from the mode (`pixelaspect` in `jfbuild/src/engine.c`, `MISTER_HYBRID`), since the core shows them all on a 4:3 screen. 2D art is never stretched down the screen: `dorotatesprite()` (`engine.c`, `MISTER_HYBRID`) draws a row of it as one line and a column as `xdim/320` pixels. At 240 lines the 320x200 screen of the menus and pictures is in the middle, the HUD at the top or bottom (`ROTATESPRITE_TOP`/`ROTATESPRITE_BOTTOM` in `build.h`, set from the game's `PANF_SCALE_TOP`/`PANF_SCALE_BOTTOM` in `panel.c` and for the mini bar in `inv.c`/`text.c`), the bottom the *HUD (Bottom)* margin above the bottom edge (`rotatesprite_hudbottom`); `y_aspect_mul` in `border.c` is 1, the status bar keeps its size. With the status bar alone (`BORDER_BAR`) the view goes on behind it to the bottom edge (`BorderSetView()`), the bar and its numbers are drawn over it every frame after the view (`drawscreen()` in `draw.c`), and the weapons sit on top of the bar (`rotatesprite_viewcover`, the lines the bar and the margin cover); the health number is drawn again also when the player is dead (`PlayerUpdateHealth()`). Smaller views with a border stay above the bar, the border filled below it too. `MiSTer_UpdateOptions()` reads the margin every frame and draws the screen again when it changes; the HUD line is greyed out at 200 lines. Only *HUD (Bottom)* (*HUD (Top)* always greyed out): at the top is nothing but the frag bar of a network game. A mode the loaded core does not have (640x240 needs host version 8) falls back to the one of 200 lines (`ScreenMode()` in `mister_port.c`).
- Main_MiSTer keeps the OSD status as raw bytes in `/media/fat/config/jfSW.CFG`; writing that file before loading the core sets options for a test without the OSD.

## Games (host version 13)

- A menu entry per game (`package/games.txt`): SW Shadow Warrior, WT Wanton Destruction, TD Twin Dragon (Danik, 2026-10-16: titles with "SW:"). `MiSTer_SelectGroup()` in `mister_port.c` builds `MH_PickGame()`'s table from the GRP files the game identified by their checksum (`grpscan.c`, any name): registered or Mac version SW, shareware or Mac demo SWS (shareware of SW), WT, TD only with a registered SW.GRP there too. A game of a menu entry that was not found has `MH_NOT_THERE` as its files (never there whatever the names in the folder: the shareware is often called SW.GRP too) and its message.
- Cheats page of the OSD (Danik, 2026-10-16): God Mode (status bit 33) and No Clipping (34) hold while on, Give All (T[56], the game's `ItemCheat()`, "swgimme") and Next Level (T[57], as an exit switch without a level of its own, only when the next map exists). `MiSTer_Cheats()` in `cheats.c`, once a frame in `RunLevel()`; not in a network game or a demo.
- Exit: `TerminateGame()` stops the sound before `uninitengine()`, which frees the cache the mixer thread still plays from: before, the game crashed at exit about every second time (SIGSEGV in `MV_Mix16BitStereo`, found 2026-10-16).
- dnkLauncher screenshots, `package/screens/<id>.png` (2026-10-25): taken on the PC with `fakecore` at 320x200, `MISTER_HYBRID_FPS=0`, the game started at a level with `MISTER_HYBRID_SET=jfSW_<id> jfsw -level<n> -s2` (default start weapons), a scripted turn or walk with a `shot` every few fields and the frame without a message kept, the PPM made a PNG and nothing else. SW: Zilla's Villa (`-level8`), a gunman coming in; WT: Restaurant (`-level8`, WT's own map), walking up to the Bento Noodle; TD: Silver Bullet (`-level12`, TD's numbers start at 5, `SWCUSTOM.TXT`), the street. Not E1L1, the README's dojo.

## Frame pacing (host version 13, measured 2026-10-16)

- Drawing ahead is in the engine (`MISTER_DRAW_AHEAD` and `misterfield()` in `jfbuild/src/sdlayer2.c`: the game's clock at the field a frame is shown at, `MH_PresentAtField()`, the SDL driver's own wait off) and switched **off** (`MISTER_DRAW_AHEAD 0`). Benchmark on the MiSTer, 640x240, E1M1 at the start turning on the spot, fields without a new frame in windows of 600 (`MISTER_HYBRID_STATS=1`), in turns: drawing ahead 6, 120, 3, 112; the old way (every frame at the next field) 0, 122, 0, 121; the released build 0, 121, 0. The old way is not worse and has one field less latency. The windows of about 120 missed fields were the MiSTer itself: Linux was busy (load 4.5, the old launcher's daemon polling for a core it did not know, many other services) and they were gone after a cold reboot (Danik, 2026-10-16).
- With `MISTER_DRAW_AHEAD 1`, `MISTER_HYBRID_AHEAD=0` gives the old way again, for comparing. `MISTER_HYBRID_STATS=1` also prints every gap of more than 4 fields with its time.
